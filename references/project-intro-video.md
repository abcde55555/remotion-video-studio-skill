# 项目介绍 / 技术分享片 SOP

用于「介绍一个开源项目/工具/产品」的视频：观众是开发者或技术决策者，目标是让他们判断「值不值得用、怎么上手」。

## 与新闻/发布片的差异

| 维度 | 新闻片 | 项目介绍片 |
|---|---|---|
| 观众 | 路人 | 开发者/潜在用户/贡献者 |
| 目标 | 知道发生了什么 | 判断能力、可信度、上手成本 |
| 叙事 | 新闻锚点→亮点→收尾 | 问题→洞察→方案→证据→架构→边界→上手 |
| 文案 | 口语为主 | 术语准确 + 短句；命令/版本/参数直接上屏 |
| 证据 | 官方 demo、数字 | 架构图、代码/命令、基准、真实运行、测试数 |
| 结尾 | 情绪/口号 | 3 条命令 + 链接 + 判断 |

## 8 段骨架

1. 一句话是什么（谁/解决什么/用什么做的）
2. 为什么现在值得看（差异化）
3. 它怎么工作（3–5 步闭环 + 流程图）
4. 证据 1：能跑（真实 demo + 环境/版本）
5. 证据 2：有数据（基准/测试/性能；没有就说没有）
6. 架构/技术选择（给能看代码的人）
7. 边界与风险（alpha/限制/法律/安全）
8. 怎么开始（命令 + 最小示例 + 文档）

## 文案规则

- 术语首次出现 5 字内解释（「clean room——不读源码，只看外部可见行为」）。
- 每个技术点配「所以呢」。
- 命令/版本/平台/License 上屏，不口播念全。
- 对比只给可核实维度，不做「最强」。
- 主动说边界；每 20–30s 给一张可截图卡片。

## 信息密度（比新闻片更严）

| 指标 | 目标 |
|---|---|
| 每屏信息点 | 8–12（含代码/命令/参数） |
| 每分钟有效事实 | 45–60 |
| 静音可读率 | ≥90% |
| 纯空镜 | 0 |
| 可带走资产 | 架构图 + 命令清单 + 对比表 + 链接 |

## 证据规则

- 每个「能」都要有截图/录屏/命令输出/测试数/Release 链接。
- 区分「官方声称」与「我验证」；没验证写「README 称」。
- 版本/日期/平台进角标，避免过期。

## 素材

- 仓库 `docs/images/*`、README 截图、Release 页、目录树、CLI 录屏。
- 架构图优先重绘（矢量/HTML），不用模糊截图。
- 标注「官方截图/官方素材」；许可证与免责声明核对。

## QA 增项

- [ ] 技术事实逐条对 README/docs/Release（版本/平台/许可/数量）
- [ ] 命令可复制可运行
- [ ] 演示环境写明（OS/版本/是否需要 key）
- [ ] alpha/限制/法律声明在片内
- [ ] 无绝对化表述，对比维度可核实

## 推荐结构比例（90s）

钩子 8s｜是什么 12s｜差异化 14s｜怎么工作 16s｜验证 14s｜技术底座 14s｜边界 8s｜上手 4s。
